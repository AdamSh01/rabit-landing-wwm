The problem

Permission isn't safety. Once it's done, it's done.

Teams give agents access so they can do real work: rotate a secret, clean up a database, ship a fix. Access answers one question, may this agent do it? It never answers the one that matters, what happens if it does? An agent can be fully authorized and still delete the wrong thing at the wrong moment, because it was wrong, or because something it read told it to.

What teams use today

Logs and monitoring tell you what happened. By then the database is gone.

Every one of these checks what an action looks like. None checks what it will do.

How it works

We check what an action will do, not what it looks like.

Rabit sits between your agent and the tools it uses. Before a write runs, three things happen:

  1. 01

    Your agent asks first.

    One call from your agent (our SDK or a plain API call) sends Rabit the action it is about to take, for example "delete the secret PROD_DB_URL".

  2. 02

    Rabit looks at your real setup and forecasts the result.

    It reads what exists and what depends on what, through read-only access. Then it forecasts what changes: what gets deleted, what breaks downstream, and whether it can be undone.

  3. 03

    Rabit decides, and tells the agent why.

    A risky action is flagged for a person, with the forecast attached, or answered BLOCK with the reason. The agent gets the reason back, so it can change its plan.

The same DELETE can be routine in one company and a disaster in another. Rules can't tell them apart. A forecast of your system can.

Review or block, never a silent pass.

Every action that reaches Rabit gets one of two answers: REVIEW, meaning a person should decide with the forecast in front of them, or BLOCK, with the reason. When Rabit isn't sure, it answers REVIEW.

A signed receipt for every decision.

Each answer is signed with a key held in AWS KMS, so you can show an auditor, a customer or your own team exactly what was decided, when, and why. You can check a receipt yourself; you don't have to take our word for it.
